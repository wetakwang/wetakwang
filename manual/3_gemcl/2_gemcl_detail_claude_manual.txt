(detail_0) 첨부 이미지 및 소스 정의 (작업 소스)
owner(=osk)는 [제미나이 설계도(Blueprint)]와 함께 아래 이미지 소스를 제공하며, 클로드코드는 엑셀을 보지 않고 제공된 설계도와 이미지들만 분석하여 작업한다.
* 주의: 아래 이미지들과 작업 중 생성한 임시 분할 컷은 최종 PNG 렌더링을 위한 소스이며, 사용자에게 개별 파일로 제출하지 않는다.

1. main.jpg (메인 이미지) :
   - 탁대표가 제품을 손에 들고 있는 대표 사진.
   - 배경 투명이 아니므로 좌우 여백/배경색 없이 가로 780px 폭을 100% 꽉 채워 도입부에 배치한다.

2. 원본 상세페이지 이미지 (순수 비주얼 추출 소스 - 텍스트 포함 절대 금지) :
   - 도매처에서 제공한 완성된 원본 상세페이지 통이미지이다.
   - [텍스트 이미지 분할 절대 금지] : 원본 이미지 안에 적힌 글자(타이틀, 설명문 등)가 포함된 채로 통째로 잘라 넣지 않는다. 이미지 속 글자는 해상도가 깨지고 폰트/어조가 충돌한다.
   - [순수 사진/그래픽만 정밀 크롭 및 업스케일] : 상세페이지의 모든 본문 텍스트는 클로드코드가 100% HTML 텍스트로 직접 작성한다. 원본 이미지에서는 [설계도의 비주얼 크롭 지시서]에 따라 **글자가 전혀 없는 순수 제품 사진, 작동 원리 도식, 인테리어 컷, 부품 디테일 컷만 오려내어** detail_1.jpg, detail_2.jpg 등으로 분할 생성하여 배치한다. (원본 크기가 작을 경우 선명도를 유지하며 780px 폭에 맞게 업스케일하여 사용한다.)

3. scene_1.jpg & scene_2.jpg (헤이젠 쇼츠 연계 고해상도 실사 컷 2장) :
   - scene_1.jpg : 실제 공간에서 조연 인물과 탁대표가 함께 있는 문제 해결/설치 스토리 실사 컷. [섹션 2: 핵심 장점 1] 스토리텔링 영역에 가로 780px 폭으로 여백 없이 배치한다.
   - scene_2.jpg : 동일 공간에서 탁대표가 제품 옆에서 카메라 정면을 바라보는 홍보/안내 실사 컷. [섹션 4 또는 5: 편의 기능/특장점 모듈] 영역에 가로 780px 폭으로 여백 없이 배치한다.

4. ending.jpg (엔딩 이미지) :
   - 탁대표가 활짝 웃으며 일하는 신뢰형 마무리 사진.
   - 좌우 여백/배경색 없이 가로 780px 폭을 100% 꽉 채워 하단에 배치한다.
   - 대체 텍스트는 반드시 `alt="찾아주셔서 참 고맙습니다 - 탁대표"`로 지정한다.

5. sign_white.png (필수 자필 서명 이미지 - 뒷배경 투명) :
   - 문구: "중랑상사 탁대표 / 믿음으로 모시겠습니다"
   - [강제 규칙 - 절대 준수] : 이 서명은 절대 HTML 텍스트나 폰트, CSS 기울임꼴로 치환하지 마라. 반드시 맨 하단 쑥색 모토 섹션(#56692f) 안에 `<img>` 태그를 사용하여 이미지 파일 그대로 삽입한다 (`style="width:540px;max-width:90%;display:inline-block;margin:0 auto;border:0;"`).

(detail_1) 상품 파악 및 시공 원칙
- All HTML Text 원칙 :
  · 제공된 [제미나이 설계도]에 적힌 모든 헤드카피, 본문 입말체 설명, 칩 키워드, 사양표, 주의사항을 단 한 글자도 임의로 요약하거나 누락하지 말고 100% 선명한 HTML 시스템 텍스트로 구현한다.
  · 어르신 맞춤 구수한 대화체(~해요, ~하셔요, ~해 드려요, 참 좋습니다)의 넉넉한 이야기 맛을 온전히 살린다.
- 시각 강조 및 줄바꿈 호흡 시공 (어르신 맞춤 가독성 확보) :
  · 설계도에 지정된 <strong> 태그와 포인트 컬러(#56692f, #C4500E)를 빠짐없이 구현하여, 검은 글씨만 빽빽하게 이어지지 않도록 시각적 포인트를 확실히 준다.
  · 문단이 너비 780px 끝까지 밀려 어색하게 꺾이지 않도록, 설계도에 표기된 <br> 태그를 정확히 살려 의미 단위(한 호흡)마다 자연스럽게 행을 넘긴다.
- 스펙 팩트 유지 및 환각 방지 :
  · 설계도에 명시된 팩트 수치만 코딩하며, 임의로 전압이나 부가 기능을 변조하지 않는다.
  · 제조사 표기: 설계도에 지정된 제조사명을 표에 기재하되, 미확인으로 명시되어 있다면 "포장 별도 표기"로 기재하고 최종 완료 메시지에 보고한다.
  · 모델명/품번 완전 배제: AI 환각 방지를 위해 영문/숫자 혼합 모델명 및 품번 코드는 상세페이지 본문 및 표 어디에도 일절 적지 않는다.

(detail_2) 규격 및 디자인 시스템 가이드
- 가로폭 : 780px 고정 (반드시 인라인 style 로만 작성하며, 외부 CSS 및 JS 사용을 금지한다).
- 색상 시스템 :
  · 기본 배경 : 크림색 (#fffefb)
  · 섹션 구분 배경 : 연한 베이지 (#f4f1ea)
  · 주 포인트/제목 : 쑥색 (#56692f)
  · 강조 칩/알약 : 테라코타 (#C4500E)
  · 본문 텍스트 : 짙은 먹색 (#2b3022) / 보조 텍스트 (#686d5c)
- 폰트 및 가독성 규격 :
  · font-family: 'Malgun Gothic', '맑은 고딕', 'Apple SD Gothic Neo', 'Noto Sans KR', sans-serif;
  · 큰 글씨 적용: 제목 44~64px (굵게), 본문 26~32px, 줄간격 1.65 이상, word-break: keep-all 필수.
- 이미지 출력 공통 스타일 :
  · main.jpg, scene_1.jpg, scene_2.jpg, ending.jpg, detail_N.jpg는 모두 `width:100%;display:block;margin:0;padding:0;border:0;`로 여백 없이 깔끔하게 배치한다.
- 렌더링 호환성 준수 :
  · 추천 칩 나열 시 flex 깨짐을 방지하기 위해 `display:flex` 대신 부모 요소 `text-align:center;`와 자식 요소 `display:inline-block;margin:6px;` 구조를 사용한다.

(detail_4) 최종 산출물 제출 규칙 (엄격 준수)
클로드코드가 작업을 마치고 owner(=osk)에게 제출하는 파일은 아래 딱 2개뿐이다.   detail.html (코드 파일) :
모든 텍스트가 선명한 HTML 코드로 작성되고, 맨 하단 서명에는 sign_white.png 이미지 태그가 적용된 완성본 코드를 단일 코드블럭으로 출력하고 detail.html 파일로 제출한다.   detail.png (이미지 파일) :
완성된 HTML을 렌더링 도구(Weasyprint, Playwright 등)를 통해 가로 780px 고정 규격으로 변환한 완성본 통이미지 파일 1장(detail.png)만 제출한다.   제출 시 필수 안내 (제조사 확인 여부 보고) :
제출 메시지에 제조사 확인 결과를 한 줄로 명확히 밝힌다.
예시 A: "상세페이지 이미지에서 확인된 제조원([제조사명])을 제품 정보 표에 반영했습니다."
예시 B: "상세페이지 이미지에서 제조사를 확인할 수 없어 '포장 별도 표기'로 기재했습니다."   제출 금지 항목 (절대 준수) :
작업 중 생성한 임시 크롭 컷(detail_1.jpg, detail_2.jpg 등)이나 main.jpg, scene_1.jpg, scene_2.jpg, ending.jpg, sign_white.png, 원본 이미지는 다운로드/공유 목록에 일절 올리지 않는다.
다운로드 카드 목록에는 오직 detail.html 과 detail.png 단 2개만 나오도록 한다.
